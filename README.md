# 招聘标准分析工具 · 使用说明（给 HR 同学的白话版）

---

## 这是什么？

简单说，这是一个**"帮你从面过的人身上总结招聘经验"**的工具。

你是不是遇到过这些情况：

- 招了大半年，总觉得筛简历全靠"感觉"，说不清楚到底什么样的人容易过？
- 一面挂了一堆人，但说不清楚他们到底都栽在哪？
- 面试官之间标准不统一，这个人说"基础好"，那个人说"基础差"，到底什么算好？
- JD 写得很漂亮，但面了一圈发现实际招到的人和 JD 写的完全不是一回事？

这个工具就是帮你解决这些问题的。

**它做的事情：** 你给它一份岗位 JD，加上几个已经面过的候选人（简历 + 面试评价 + 通过/没通过的结果），它会帮你产出一份完整的招聘标准报告，告诉你：

1. **什么样的简历容易被约面**（筛简历关键词清单）
2. **怎么在招聘系统里搜人**（直接复制粘贴的搜索表达式）
3. **每一轮面试主要在考察什么**（一面卡什么、二面卡什么、终面卡什么）
4. **候选人为什么通过、为什么被淘汰**（逐个分析）
5. **接下来怎么改进筛选和面试**（具体可执行的建议）

---

## 谁能用？

**任何公司、任何招聘系统都能用。**

这个工具不绑定任何特定的招聘系统（不管你用的是北森、Moka、大易、肯耐珂萨、LinkedIn Recruiter，还是公司自己开发的系统，都可以）。所有候选人数据由你手动提供——你从招聘系统里把简历和面评复制出来，发给它就行。

**适合的岗位：** 算法、工程、产品、运营、设计……各类岗位都适用。技术岗的效果最好（因为技术方向词容易统计），非技术岗也能用（分析框架是通用的）。

**适合的场景：**
- 校招/社招启动前，先从历史候选人中沉淀筛选标准
- 招了一段时间发现通过率低，想搞清楚问题出在哪
- 面试官团队标准不统一，想做一次面试官对齐
- JD 和实际招人情况脱节，想校准 JD
- 新人 HR 接手一个岗位，想快速了解"这个岗到底要什么样的人"

## 怎么用？（3 步走）

### 第一步：准备材料

你需要准备以下东西：

#### 1. 岗位 JD（必须）

就是这个岗位的招聘描述。可以是：
- 一段文字（直接复制粘贴）
- 一个文档链接（飞书、钉钉、Notion 等）
- 招聘系统里的岗位描述页面链接

#### 2. 样本候选人（必须，至少 2 位，建议 5 位以上）

每位候选人需要提供三样东西：

| 材料 | 说明 | 从哪来 |
|---|---|---|
| **简历** | 候选人的简历内容 | 从招聘系统导出/复制，或者候选人发给你的简历 |
| **面试评价** | 面试官写的评语、面试总结、面试记录等 | 从招聘系统的面试评价模块复制，或者你自己记录的面试要点 |
| **结果标签** | 这个人最终通过了还是淘汰了，停在哪一轮 | 你自己知道 |

**结果标签怎么写？** 用大白话描述就行，比如：
- "简历过了，一面挂了"
- "一面过了，二面挂了"
- "全过了，发了 offer"
- "只过了简历，还没面"

不用记那些英文标签（r1_pass 之类的），你用大白话说，工具会自动转换。

#### 3. 其他（可选）

- **团队介绍/业务背景文档**：如果有，可以帮助工具更好地理解这个岗位的业务语境
- **额外说明**：比如"这是实习岗，重点看科研潜力"或者"这个岗偏工程落地，不看论文"

### 第二步：发给工具

把准备好的材料直接发给它就行，格式不限。你可以这样写：

```
帮我分析一下这个岗位的招聘标准：

【JD】
<这里粘贴 JD 文本，或者放链接>

【候选人 A】
简历：<粘贴简历文本 或 放链接>
面评：<粘贴面试评价文本>
结果：一面过了，二面挂了

【候选人 B】
简历：<粘贴简历文本 或 放链接>
面评：<粘贴面试评价文本>
结果：一面挂了

【候选人 C】
...

【额外说明】
这是校招岗，base 上海，重点看工程落地能力。
```

> **小提示：** 如果你觉得材料太多，可以分几次发——先发 JD，再逐个发候选人。工具会等你材料齐了再开始分析。

### 第三步：拿到报告

工具会按 6 个步骤分析，最后给你一份完整的报告。报告是 Markdown 格式，你可以：

- **直接阅读**：在对话框里就能看
- **复制到文档平台**：全选复制，粘贴到飞书文档、钉钉文档、企业微信文档、Notion、Confluence、Google Docs 等任何地方
- **如果用飞书**：可以要求直接创建飞书文档，给你一个链接

**报告会包含什么？** 参见下面的"输出长什么样"章节。

---

## 输出长什么样？

最终报告会有 8 个章节，下面是每一章的"人话版"介绍：

| 章节 | 人话解释 | 你能用它做什么 |
|---|---|---|
| **1. 核心结论** | 3-5 条最重要的发现，一句话一条 | 没时间看全文？只看这一章就行 |
| **2. 岗位画像** | 这个岗位要什么样的人（学历、方向、硬门槛等） | 给新人 HR 或新面试官快速了解岗位 |
| **3. 样本与数据来源** | 这次分析用了多少人、怎么分组的 | 判断这个分析靠不靠谱（人越多越靠谱） |
| **4. 简历筛选关键词** | 分类列出的关键词，每个词标了"多少通过的人有这个词" | 筛简历时对照看，有这些词的优先约面 |
| **5. 布尔检索式** | 两套可以直接复制粘贴到招聘系统搜索框的搜索表达式 | 去招聘系统搜人时直接用，不用自己拼条件 |
| **6. 各轮面试考察要点** | 一面/二面/终面各一张表，写了每轮该问什么、什么算通过、什么情况会挂 | 给面试官做参考，统一面试标准 |
| **7. 通过/淘汰归因** | 逐个候选人分析：因为什么过的、因为什么挂的 | 看具体案例，验证前面的结论是否合理 |
| **8. 策略建议** | 具体可执行的改进建议（如"一面加一道项目深挖题"） | 直接照着做，改进你的筛选和面试流程 |

## 常见问题

### Q1：我只有 JD，还没面过人，能用吗？

能用，但效果会打折扣。没有样本候选人，工具只能帮你做"理想画像 + JD 关键词提取"，没法告诉你"实际通过的人是什么样"。它会明确告诉你"缺少样本，以下仅为理想画像"。

建议：先面几个人，积累 3-5 个样本后再做正式分析。

### Q2：只有 2-3 个样本，分析结果靠谱吗？

能做，但所有结论都会标注"样本量小，仅供参考"。就像只问了 3 个人的意见，不能代表所有人。建议：

- 5 个以上样本：可以做初步分析，结论有一定参考价值
- 10 个以上样本：结论比较可靠，可以作为正式招聘标准
- 20 个以上样本：非常可靠，可以用来培训新面试官

### Q3：面试评价写得很简单（比如只有"基础不好"），能用吗？

能用，但分析深度会受影响。工具只能从你提供的信息中分析，如果面评只有"基础不好"四个字，它只能归纳出"基础知识不足"，没法告诉你具体是哪方面的基础（是算法基础？还是工程基础？）。

建议：如果可能，尽量提供详细的面评，包括面试官问了什么问题、候选人怎么回答的。信息越详细，分析越深入。

### Q4：布尔检索式在我的招聘系统里用不了怎么办？

不同招聘系统的搜索语法可能略有差异。工具给的是通用布尔语法（AND/OR/NOT/括号/引号），绝大多数系统都支持。如果你的系统不支持：

1. 先看看系统帮助文档，了解它支持什么搜索语法
2. 把通用检索式按你系统的语法微调一下（通常只是符号不同，逻辑是一样的）
3. 如果实在不确定，把关键词清单（第 4 章）拿去手动筛选，效果也差不多

### Q5：候选人数据安全吗？会不会泄露？

安全。工具遵守以下规则：

1. 你提供的所有候选人数据**仅用于本次分析**，不会用于其他用途
2. 最终报告中，手机号、邮箱、身份证号等敏感信息会**自动脱敏**
3. 面试评价原文**不会**出现在最终报告中，只出现归纳后的结论
4. 任何登录凭证（密码、Cookie 等）**不会**被保存

### Q6：我不懂技术，能看懂报告吗？

能。报告是用大白话写的，每个技术术语都会有解释。比如"布尔检索式"会解释成"就是招聘系统搜索框里的高级搜索条件组合"。如果你看到不懂的词，直接问工具，它会用更通俗的话解释。

### Q7：分析一次要多久？

取决于样本数量。一般来说：

- 2-3 个候选人：约 3-5 分钟
- 5-10 个候选人：约 5-10 分钟
- 10 个以上：约 10-15 分钟

工具会边分析边告诉你进度，你可以随时问"到哪一步了"。

### Q8：分析完之后，我想加几个候选人重新分析，可以吗？

可以。直接把新的候选人发过去，说"加上这几个重新分析"就行。工具会把新旧样本合在一起重新跑一遍。

## 一个完整的使用示例

假设你是校招 HR，要招"大模型算法工程师"，面了 5 个人，想总结一下筛选标准。你可以这样发：

```
帮我分析大模型算法工程师（校招）的招聘标准。

【JD】
岗位名称：大模型算法工程师（2027届校招）
岗位职责：
1. 参与大模型预训练和微调工作
2. 探索多模态方向的算法优化
3. 推动算法在实际业务中的落地
岗位要求：
1. 2027届硕士及以上学历，计算机/数学/统计相关专业
2. 熟悉大模型相关技术，有预训练或微调经验优先
3. 熟悉 Agent、RAG 等方向优先
4. 有顶会论文或开源项目经验优先
base：上海

【候选人 A】
简历：<粘贴简历>
面评：<粘贴面评>
结果：一面过了，二面挂了

【候选人 B】
简历：<粘贴简历>
面评：<粘贴面评>
结果：全过了，发了 offer

【候选人 C】
简历：<粘贴简历>
面评：<粘贴面评>
结果：一面挂了

【候选人 D】
简历：<粘贴简历>
面评：<粘贴面评>
结果：一面过了，二面过了，终面挂了

【候选人 E】
简历：<粘贴简历>
面评：<粘贴面评>
结果：全过了，已入职

【额外说明】
这个岗偏工程落地，论文不是必须的，但要有实际项目经验。
```

然后工具就会开始分析，几分钟后给你一份完整的报告。

## 最后说两句

这个工具的核心价值不是"替你做决定"，而是**"帮你把模糊的招聘经验变成清晰的、可复用的标准"**。

筛简历靠感觉、面试靠临场发挥、标准靠口口相传——这些是很多招聘团队的痛点。这个工具帮你把"感觉"变成"数据"，把"经验"变成"标准"，让招聘从"玄学"变成"科学"。

但记住：**工具是辅助，最终判断还是靠人。** 报告里的结论是基于历史样本的统计规律，不代表未来一定如此。用报告指导你的招聘工作，但也要保持灵活，根据实际情况调整。

祝招聘顺利！
